API environment

Set these on the F-Motion API process only. Never put them in VITE_* or commit partner secrets.

  • ✓
    FENGINE_IMPORT_TOKEN Shared Bearer for POST /v1/integrations/project-imports. At least 32 characters.
  • ✓
    FENGINE_IMPORT_OWNER_ID UUID of the allowlisted owner who receives imported drafts.
  • ✓
    FENGINE_IMPORT_MEDIA_ORIGINS Comma-separated HTTPS origins allowed in media_urls. Other URLs are skipped.
  • ✓
    FENGINE_WEB_ORIGIN Public studio origin used to build projectUrl.
  • ✓
    FENGINE_RENDER_NOTIFY_ORIGINS Comma-separated HTTPS origins allowed for notify_url.
  • ✓
    FENGINE_RENDER_NOTIFY_SECRET HMAC secret for X-F-Motion-Signature. Optional; import token is the fallback.
Import and open
curl -X POST https://api.f-motion.com/v1/integrations/project-imports \
  -H "Authorization: Bearer $FENGINE_IMPORT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "external_id": "cms:gallery:weekend",
    "title": "Weekend portraits",
    "caption": "Quiet frames from the session.",
    "call_to_action": "Open the full gallery.",
    "architecture": {
      "duration_seconds": 15,
      "goal": "promote",
      "audience": "social",
      "structure": "story_arc",
      "tone": "cinematic",
      "pace": "balanced",
      "media": "own"
    },
    "media_urls": ["https://media.example.com/galleries/weekend/1.jpg"],
    "notify_url": "https://cms.example.com/api/integrations/fmotion/notify"
  }'

Headless render

Use an owner fm_ API key. Pass notify_url so F-Motion POSTs signed JSON on complete. Verify X-F-Motion-Signature, then GET download_path. If you skip notify, poll SSE /v1/render-jobs/{id}/events.

Headless render
curl -X POST https://api.f-motion.com/v1/projects/$PROJECT_ID/render \
  -H "Authorization: Bearer $FMOTION_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "kind": "preview",
    "notify_url": "https://cms.example.com/api/integrations/fmotion/notify",
    "external_id": "cms:gallery:weekend"
  }'
