## Why this matters

Users should be able to leave F-Motion for advanced work without F-Motion
becoming a full nonlinear editor. A final MP4 imports everywhere but flattens
captions and scene boundaries; vendor project formats are fragmented and cannot
honestly be represented by one "export to all editors" button. This plan first
ships a portable, testable bundle and only advertises editor-specific timelines
after real import validation.

## Supported first release

One background `editor_bundle` artifact containing:

```text
f-motion-project/
  README.txt
  final.mp4
  captions.srt
  project.json
  attribution.txt
  scenes/
    01.mp4
    02.mp4
    ...
```

- `final.mp4`: approved final from plan 016, copied without re-encoding.
- `scenes/*.mp4`: transformed, timeline-ready scene clips rendered at the final
  profile without burned captions; crop/motion are baked in.
- `captions.srt`: UTF-8 captions with project-global timestamps derived from
  authoritative scene cues.
- `project.json`: versioned neutral manifest with relative paths, frame rate,
  dimensions, ordered durations, captions, crop/motion facts, and attribution.
- `attribution.txt`: provider/creator/source-page credits for included scenes.
- `README.txt`: concise import instructions for Premiere Pro, DaVinci Resolve,
  Final Cut Pro, and CapCut, stating that the first release is a media bundle,
  not a native editable project.

Do not include original/quarantine/sealed Pexels objects. User-owned originals
are also deferred; this keeps one predictable rights policy.

## Interchange truth to preserve

- Final Cut Pro accepts FCPXML generated by third parties:
  `https://support.apple.com/guide/final-cut-pro/use-xml-to-transfer-projects-verdbd66ae/mac`.
- Adobe states modern `.fcpxml` cannot be imported directly into Premiere; a
  separate Premiere-compatible XML path or conversion is required:
  `https://helpx.adobe.com/premiere/desktop/organize-media/import-files/migrate-from-final-cut-pro-x.html`.
- CapCut states it does not directly import third-party project files; support
  it through MP4/scene media and SRT only:
  `https://www.capcut.com/help/how-to-export-pro-project`.
- AAF is intentionally rejected for this release due implementation complexity
  and poor leverage for the current simple one-track storyboard.

## Steps

### Step 1: Freeze the versioned portable manifest and SRT rules

Define `EditorBundleManifestV1` with no credentials, signed URLs, object keys,
owner IDs, local absolute paths, or provider download URLs. It may contain:

- format version and project revision;
- width, height, rational frame rate, and total duration;
- ordered scene ID, relative media path, duration, motion/crop/audio facts,
  caption text/cues, and optional attribution display data;
- relative `final.mp4` and `captions.srt` paths.

Create pure serialization functions. Convert scene-local cues to project-global
SRT timestamps by cumulative scene duration. Use stable `HH:MM:SS,mmm`, CRLF or
LF consistently, sequential cue numbers, and UTF-8. Reject traversal/control
characters in derived filenames and ensure all bundle paths are fixed by code,
not user input.

**Verify**: engine/contracts tests compare exact JSON/SRT golden fixtures,
including Unicode, millisecond carry, empty captions, multiple cues, and scene
boundaries. `npm test --workspace packages/reel-engine` → exit 0.

### Step 2: Add a caption-free scene-render mode

Extend the deterministic renderer with a closed option for `captions: "burn" |
"separate"`. Existing preview/final jobs always use `burn`; editor-bundle scene
clips use `separate` and therefore omit ASS filters while keeping crop, motion,
duration, audio level, codec, dimensions, and frame rate.

Do not create a second crop/motion implementation. Do not change final MP4
semantics. Probe every scene clip for profile, duration, and streams before it
enters the archive.

**Verify**: worker tests show the same scene has caption filters in burn mode,
none in separate mode, and otherwise equivalent deterministic arguments.

### Step 3: Add an editor-bundle background artifact

Extend plan 015's artifact model with `editor_bundle` only if it can preserve:

- one canonical bundle per owner/project/revision/final-result identity;
- immutable project snapshot and profile;
- queued/running/complete/failed/cancelled progress;
- a result content type and `.zip` object key distinct from MP4 results.

Bundle admission requires a completed, current final result from plan 016.
The worker downloads/copies that exact final, renders caption-free scene clips,
writes manifest/SRT/attribution/readme files in a private temp directory, and
streams a ZIP to private object storage. Always remove temp files and losing
uploads on failure/cancellation.

If a ZIP dependency is required, choose one small maintained streaming package,
install it with an exact version, commit lockfile changes, and run
`npm audit --omit=dev`. Do not shell out to an unpinned system `zip` command.

Apply hard ceilings before work: maximum eight scenes, maximum aggregate
transformed media bytes, maximum archive bytes, bounded execution time, and no
symlinks. CRC/archive errors fail the job.

**Verify**: worker integration opens the ZIP and asserts the exact allowlisted
entry set, no absolute/traversal paths, valid MP4 entries, exact manifest/SRT,
and cleanup after injected upload/archive failure.

### Step 4: Expose owner-scoped bundle export and UI

Add API endpoints to create/follow/cancel/download the bundle using the same SSE
and signed-attachment patterns as render jobs. Return typed 422 for missing or
stale final, typed capacity error, and typed terminal failure. Never return
storage object keys.

On the final delivery screen add `Export for video editor`. Explain before
starting:

- compatible media bundle for Premiere Pro, Resolve, Final Cut, and CapCut;
- captions remain editable through SRT;
- crop/motion are baked into per-scene clips;
- it is not a native vendor project.

Show progress/cancel/retry and download `f-motion-<safe-name>-editor-bundle.zip`.

**Verify**: API/web tests cover owner scope, stale final, duplicate request,
cancel/retry, safe filename, and truthful copy. E2E downloads and inspects the
archive from a multi-scene project.

### Step 5: Run editor-specific compatibility spikes without false promises

After the portable bundle is green, create isolated golden prototypes for:

- FCPXML for Final Cut Pro and a named tested DaVinci Resolve version;
- Premiere-compatible legacy Final Cut Pro XML (`xmeml`) or simple CMX 3600 EDL
  for the one-video-track subset.

The prototypes must reference relative `scenes/*.mp4` paths and preserve ordered
duration/frame rate. They may be checked into test fixtures, but do not put an
editor-specific button in production until a maintainer records:

- editor name and exact version;
- import steps;
- successful media relink;
- verified scene order/duration/frame rate/captions;
- unsupported features and screenshots/logs stored outside the public export.

CapCut receives no native-project spike because its official documentation says
third-party project import is unsupported. Use bundle+SRT instructions only.

**Verify**: XML is well-formed and golden tests pass. Manual vendor import is a
required release gate, not replaceable by XML parsing.

Write a host-owned export policy that names what is included/excluded and why.
Record that raw Pexels source inclusion requires a separate reviewed provider
decision. Include attribution even where not legally required because the app
already displays it and it helps users track sources.

## Test plan

- Exact versioned manifest excludes private/internal identifiers and URLs.
- SRT handles cumulative timing, Unicode, empty captions, and millisecond
  boundaries.
- Separate-caption scene clips omit ASS but preserve all other rendering facts.
- ZIP contains only allowlisted relative regular-file entries.
- Injected render/archive/upload/cancel failures clean all temporary/remote
  partials.
- Bundle creation is owner-scoped, canonical, and requires a current final.
- E2E opens the bundle and probes final plus every scene clip.
- Vendor XML prototypes remain hidden unless exact-version manual import proof
  is recorded.

## STOP conditions

- Stop if raw Pexels media appears necessary; obtain a maintainer-approved
  rights decision instead of inferring permission.
- Stop if a ZIP implementation requires buffering the whole bundle in API or
  browser memory; use a bounded worker stream or report alternatives.
- Stop if plan 015's result model cannot represent a non-MP4 artifact without
  ambiguous fields; design a forward migration before coding.
- Stop before advertising any native editor format without real exact-version
  import evidence.
- Stop if a dependency introduces high/critical production advisories.
- Stop after two failed attempts at any verification step.

## Maintenance notes

- The neutral manifest should remain the source for every future exporter;
  vendor serializers must not read database rows directly.
- Editor formats change. Compatibility claims need named versions and periodic
  revalidation.
- Prefer portable transformed media over maintaining proprietary project-file
  generators. Add a vendor exporter only when user evidence justifies it.
